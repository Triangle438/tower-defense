# Tower Defense

A tower defense game that runs in the browser. Enemies walk a winding path towards your base, you build and upgrade towers to stop them, and every wave is harder than the last.

Built with **React 18**, **TypeScript**, the **Canvas API** and plain **CSS**, bundled with **Vite**, with unit tests in **Vitest**. No game engine and no runtime dependencies besides React.

## How to play

- Pick a tower, then click a free tile next to the path to build it. Hover to preview its range.
- Press **Start wave** (or `Space`) when you are ready. Between waves nothing moves, so take your time.
- Click a tower to **upgrade** (up to level 3) or **sell** it for 70% of what you invested.
- Every enemy that reaches your base costs lives. At 0 lives the game is over. Your best score is saved in the browser.

| Tower | Cost | What it does |
| --- | --- | --- |
| **Arrow** | 50 | Fast single shots at the enemy closest to your base |
| **Cannon** | 110 | Slow shells that damage every enemy around the target |
| **Frost** | 80 | Chills all enemies in range and slows them by half |

Enemies: grunts, fast runners (from wave 3), tough tanks (from wave 5) and a boss every 10th wave. Enemy health grows 12% per wave, compounding, so every run ends eventually.

**Controls:** `1` `2` `3` pick a tower, arrow keys move the cursor, `Enter` builds or selects, `Space` starts the wave, `U` upgrades, `X` sells, `P` pauses, `Esc` or right-click cancels. It also works with touch, and the game can run at 1x, 2x or 4x speed.

## How it works

- **Pure, deterministic engine** (`src/game/engine.ts`): `reduce(state, action) => newState`, used with React's `useReducer`. There is **no randomness at all**: waves are generated by formula and shots never miss, so the same actions always produce exactly the same game.
- **Fixed time step** (`src/hooks/useTowerDefense.ts`): the game loop turns real time into fixed 1/30 s ticks, so the game plays the same on a 60 Hz and a 144 Hz screen, and speed 2x or 4x just runs more ticks per frame.
- **Path as data** (`src/game/path.ts`, `config.ts`): a map is a list of corner points. From it the game works out which tiles are blocked, the total length, and where an enemy is at any distance travelled. Adding a new map means adding one entry.
- **Rendering is a pure function of the state** (`src/game/render.ts`): shots, blasts and frost pulses are short-lived effects stored in the state, so the picture can be tested and reproduced.
- **Accessibility**: playable by keyboard only, the message log is an `aria-live` region, and buttons use `aria-pressed`.

## Tests

`npm test` runs 41 tests, including:

- path geometry: tiles covered, corner turns and clamping
- wave generation: composition per wave, boss timing, difficulty curve
- building rules: path, occupied tiles, map edges, gold, upgrades, selling refunds
- combat: range, cooldowns, focus on the leading enemy, cannon splash, frost slow, rewards, lives and game over
- **a simulation test**: a bot plays 15 waves of building and upgrading, and after every single tick the test checks that gold and lives never go negative, no two towers share a tile and enemy ids and health stay valid. A second test checks that the same bot plays the same game twice

The same bot was used to tune the difficulty: with up to 40 towers it survives until the wave-30 boss wave.

## Structure

```
src/
  game/         config, path, waves, engine, render, bot (test helper), all with tests, no React
  components/   GameCanvas, Hud, Controls, BuildPanel, TowerInfo, MessageLog
  hooks/        useTowerDefense (reducer, game loop, keyboard), useLocalStorage
```

## Getting started

Requires Node.js 18+.

```bash
npm install
npm run dev      # start dev server
npm test         # run unit tests
npm run build    # type-check and build to dist/
npm run preview  # preview the production build
```
